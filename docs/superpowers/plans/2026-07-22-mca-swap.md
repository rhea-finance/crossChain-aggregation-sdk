# MCA Swap Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add complete MCA deposit and withdraw support to the unified Swap SDK, including collateral fields, NEAR direct execution, Intents relayer submission, multi-chain signing, reporting, status polling, and history filtering.

**Architecture:** Expose MCA as `SwapClient.mca`, implemented by a focused `McaSwapService` that composes the existing quote, build, executor, report, status, and history surfaces. Keep ordinary swap behavior unchanged and model MCA quote/execution paths as strict discriminated unions.

**Tech Stack:** TypeScript 5, Vitest, Zod 4, native Fetch API, existing executor registry.

## Global Constraints

- Implement only MCA behavior inside Swap; do not implement MCA creation, wallet binding, lending account queries, borrowing, or portfolio fetching.
- Work directly in `/Users/ranzhang/Documents/code/wb/crossChain-aggregation-sdk`.
- Do not restore intentionally deleted legacy files.
- Do not create a git commit unless the user explicitly authorizes it.
- Do not add wallet vendor dependencies; all wallet signing remains adapter-driven.
- Do not add a fixed API token, JWT, access token, private key, or mnemonic.
- Preserve the existing ordinary swap API and runtime behavior.
- All amounts remain base-unit non-negative decimal strings unless a field is explicitly a Burrow decimal value.
- Follow strict TDD: add one failing behavior test, run it and observe the expected failure, implement the minimum behavior, then rerun it.
